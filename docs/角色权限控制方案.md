# 角色权限控制方案

## 一、概述

### 1.1 方案目标

用基于角色的 CRUD 操作级权限控制，彻底替代当前硬编码的 `is_admin()` / `is_super_admin()` / `admin_required` 体系。

### 1.2 设计原则

- **简洁**：只使用一个装饰器 `@require_permission('permission_code')`，不设计专用装饰器
- **CRUD 操作级粒度**：每个模块的查看/新增/编辑/删除等操作作为独立权限单元，角色配置可访问哪些操作权限
- **彻底替代**：一次性替换旧体系，不保留任何旧接口

## 二、数据模型设计

### 2.1 角色表 `role`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer, PK | 主键 |
| name | String(50), unique, not null | 角色名称，如"超级管理员" |
| code | String(50), unique, not null | 角色编码，如"super_admin" |
| description | String(200) | 角色描述 |
| is_system | Boolean, default=False | 是否系统内置角色（不可删除） |
| sort_order | Integer, default=0 | 排序权重 |
| created_at | DateTime | 创建时间 |

### 2.2 角色-权限关联表 `role_permission`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer, PK | 主键 |
| role_id | Integer, FK(role.id), not null | 角色ID |
| permission_code | String(50), not null | 权限编码（格式：`模块.操作`，如 `user.view`） |

唯一约束：`(role_id, permission_code)`

### 2.2.1 模型文件路径

角色相关模型文件放置在 `models/role/` 子文件夹下，与 `models/supply/`（办公用品）保持一致的组织方式：

- `models/role/__init__.py`
- `models/role/role.py`（角色表模型）
- `models/role/role_permission.py`（角色-权限关联表模型）

### 2.3 User 模型修改

**删除：**
- `role` 字段（原 String 类型角色字段）

**新增：**
- `role_id` 字段，外键关联 `role.id`

伪代码示意：
```
User:
  - 删除: role (String)
  - 新增: role_id (Integer, FK -> role.id)
  - 新增: has_permission(permission_code) 方法
  - 删除: is_admin() 方法
  - 删除: is_super_admin() 方法
```

## 三、单一装饰器设计

### 3.1 `@require_permission('permission_code')` 装饰器

这是系统中唯一的权限装饰器，用于保护路由函数。

**工作原理：**
1. 检查当前用户是否已登录 → 未登录则重定向到登录页
2. 检查当前用户的角色是否拥有该权限 → 无权限则返回 403 页面
3. 超级管理员角色（code 为 `super_admin`）自动拥有所有权限，无需在 `role_permission` 表中逐条配置

伪代码示意：
```
def require_permission(permission_code):
    def decorator(f):
        def decorated_function(*args, **kwargs):
            if not current_user.is_authenticated:
                # 未登录 → 重定向到登录页
                redirect(login)
            
            if not current_user.has_permission(permission_code):
                # 无权限 → 返回403
                abort(403)
            
            return f(*args, **kwargs)
        return decorated_function
    return decorator
```

**使用示例：**
```
@require_permission('user.view')     # 用户列表页
@require_permission('user.create')   # 新增用户
@require_permission('user.edit')     # 编辑用户
@require_permission('user.delete')   # 删除用户
@require_permission('user.export')   # 导出用户
@require_permission('user.import')   # 导入用户
```

### 3.2 `has_permission(permission_code)` 方法

在 User 模型上提供此方法，用于后端逻辑判断和前端模板渲染。

伪代码示意：
```
def has_permission(permission_code):
    if not self.is_authenticated:
        return False
    
    # 超级管理员自动拥有所有权限
    if self.role and self.role.code == 'super_admin':
        return True
    
    # 查询 role_permission 表
    if self.role:
        return permission_code in [p.permission_code for p in self.role.permissions]
    
    return False
```

## 六、前端权限控制

### 6.1 模板中的权限判断

使用 `current_user.has_permission('permission_code')` 替代 `current_user.is_admin()`。

**导航菜单（header.html）：**

替换前：
```html
{% if current_user.is_admin() %}
    <a href="...">用户管理</a>
{% endif %}
```

替换后：
```html
{% if current_user.has_permission('user.view') %}
    <a href="...">用户管理</a>
{% endif %}
```

**功能入口页（other_index.html）：**

替换前：
```html
{% if current_user.is_admin() %}
    <div>费用补贴</div>
    <div>固定资产</div>
{% endif %}
```

替换后：
```html
{% if current_user.has_permission('fee_subsidy.view') %}
    <div>费用补贴</div>
{% endif %}
{% if current_user.has_permission('fixed_asset.view') %}
    <div>固定资产</div>
{% endif %}
```

**功能按钮/操作区域（CRUD 级别控制）：**

替换前：
```html
{% if current_user.is_super_admin() %}
    <button>系统初始化</button>
{% endif %}
```

替换后：
```html
{% if current_user.has_permission('system_settings.initialize') %}
    <button>系统初始化</button>
{% endif %}
```

CRUD 级别按钮控制示例：
```html
<!-- 列表页：根据操作权限控制按钮显示 -->
{% if current_user.has_permission('user.create') %}
    <button>新增用户</button>
{% endif %}
{% if current_user.has_permission('user.export') %}
    <button>导出</button>
{% endif %}
{% if current_user.has_permission('user.import') %}
    <button>导入</button>
{% endif %}

<!-- 每行操作：根据操作权限控制 -->
{% if current_user.has_permission('user.edit') %}
    <button>编辑</button>
{% endif %}
{% if current_user.has_permission('user.delete') %}
    <button>删除</button>
{% endif %}
```

### 6.2 导航菜单动态显示

每个导航菜单项根据用户 `.view` 权限决定是否显示，无对应 `.view` 权限的菜单项不渲染。

- 入口：系统设置模块中新增"角色管理"子页面

### 7.3 角色详情页

角色详情页用于查看和管理当前角色下的用户，支持用户的添加与移除操作。

#### 用户列表展示

- 进入角色详情页后，展示当前角色下的所有用户列表
- 列表显示用户基本信息：姓名、用户名、部门
- 支持分页显示，默认每页 20 条
- 用户列表为空时显示空状态提示

#### 手动添加用户

- 提供"添加用户"按钮，点击后弹出用户选择弹窗
- 弹窗中展示系统内尚未分配到当前角色的用户列表
- 支持按姓名、用户名搜索筛选用户
- 选中单个用户后确认添加，该用户即加入当前角色

#### 批量添加用户

- 在用户选择弹窗中支持多选模式
- 勾选多个用户后一次性批量添加到当前角色
- 弹窗底部显示已选用户数量，确认后批量写入

#### 单个移除用户

- 用户列表每行提供"移除"操作按钮
- 点击后弹出确认提示，确认后将该用户从当前角色中移除
- 移除后该用户的 `role_id` 置为空（即无角色状态）

#### 批量移除用户

- 用户列表支持多选模式，勾选多个用户
- 列表顶部显示"批量移除"按钮，点击后弹出确认提示
- 确认后将所选用户从当前角色中批量移除

#### 用户搜索/筛选

- 在添加用户弹窗中提供搜索输入框
- 支持按姓名、用户名进行模糊搜索
- 搜索结果实时更新，无匹配时显示空状态提示

### 7.4 约束规则

- 系统内置角色不可删除，但可修改权限
- 超级管理员角色的权限不可修改（始终全部）
- 只有拥有 `role.view` 权限的用户才能访问角色管理页面
- 角色编码（code）创建后不可修改

### 7.5 文件路径

角色管理相关文件放置在子文件夹下，与 `supply`（办公用品）模块保持一致的组织方式：

- 蓝图文件：`blueprints/role/` 子文件夹（如 `blueprints/role/role.py`、`blueprints/role/role_operations.py` 等）
- 模板文件：`templates/role_manage/` 子文件夹

1. **创建 Role 和 RolePermission 数据表** — 新增 `models/role/role.py`、`models/role/role_permission.py`，定义表结构

3. **实现 require_permission 装饰器** — 在 `utils/auth.py` 中实现，替换旧的 `admin_required`
4. **实现 has_permission 方法** — 在 User 模型上实现，含超级管理员自动放行逻辑
5. **初始化默认角色和权限数据** — 创建 4 个内置角色及其 CRUD 级别权限预设
6. **替换所有 @admin_required** — 按蓝图文件及路由功能逐一替换为 `@require_permission('对应权限编码')`
7. **替换所有模板中的 is_admin() / is_super_admin()** — 替换为 `current_user.has_permission('对应权限编码')`
8. **实现角色管理界面** — 角色列表页、角色编辑页（含 CRUD 级别权限勾选），蓝图放置在 `blueprints/role/` 子文件夹，模板放置在 `templates/role_manage/` 子文件夹
9. **清理旧代码** — 删除 `admin_required`、`is_admin()`、`is_super_admin()`、`USER_ROLES`、`USER_DEFAULT_ROLE` 等废弃内容
