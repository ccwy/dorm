# 后勤维修模块设计方案

## 一、模块概述

基于现有行政后勤管理系统架构，新增后勤维修模块，实现宿舍维修工单的全流程管理，包括用户提交维修工单、自动关联住宿房间、维修类型配置、照片视频上传、自动/手动分配维修人员、维修人员处理工单、管理员管理工单等功能。

**核心定位**：后勤维修模块面向住宿用户提供便捷的维修报修入口，同时为维修人员和管理员提供工单管理能力。用户创建维修工单时自动关联其住宿房间号（可修改），标题由描述前20字自动生成，维修类型从系统配置读取，支持上传不限数量的照片和视频，工单可自动或手动分配给维修员角色用户。

**与留言工单系统的区别**：留言工单（ticket）是通用的留言反馈系统，维修工单（maintenance）是专门的后勤维修流程管理，增加了房间关联、维修类型、自动分配、维修员角色等专业字段和流程。

## 二、架构设计原则

严格遵循项目现有架构模式：
- **Blueprint分层模式**: 用户蓝图(ticket_user模式) + 管理蓝图(ticket_admin模式) + API蓝图(JSON响应+媒体服务)
- **模型子文件夹模式**: `models/maintenance/` 子文件夹，参照 `models/role/` 和 `models/supply/` 的组织方式
- **蓝图子文件夹模式**: `blueprints/maintenance/` 子文件夹，参照 `blueprints/role/` 和 `blueprints/supply/` 的组织方式
- **配置驱动**: 维修类型从 SystemConfig 读取（category: maintenance），功能开关 `FEATURE_MAINTENANCE_MANAGE_ENABLED`
- **权限控制**: `@require_permission` 装饰器 + `@login_required` 认证，维修员角色(maintenance_staff)拥有维修操作权限
- **媒体管理**: 参照 TicketPhotoManager 创建 MaintenancePhotoManager，支持图片和视频，增加临时上传机制
- **前端技术栈**: TailwindCSS + FontAwesome 4.7 + Jinja2模板
- **自动分配**: 系统自动分配到维修人员（轮询或空闲优先），也支持管理员手动指定

### 3.1 维修工单表 - MaintenanceOrder

文件: `models/maintenance/maintenance_order.py`

```python
from datetime import datetime
from utils.db import db

class MaintenanceOrder(db.Model):
    """维修工单表"""
    __tablename__ = 'maintenance_orders'

    # 核心字段
    id = db.Column(db.Integer, primary_key=True)
    order_number = db.Column(db.String(50), unique=True, nullable=False, comment='工单编号（自动生成：WX+年月+4位序号）')
    title = db.Column(db.String(255), nullable=False, comment='工单标题（取描述前20字自动生成）')
    description = db.Column(db.Text, nullable=False, comment='问题描述')

    # 用户与房间信息
    user_id = db.Column(db.Integer, db.ForeignKey('users.id', ondelete='CASCADE'), nullable=False, comment='报修用户ID')
    room_id = db.Column(db.Integer, db.ForeignKey('rooms.id', ondelete='SET NULL'), nullable=True, comment='关联房间ID（自动关联，可修改）')
    room_info = db.Column(db.String(200), nullable=True, comment='房间信息文本（楼栋+房间号，冗余存储）')

    # 维修类型与优先级
    maintenance_type = db.Column(db.String(50), nullable=False, comment='维修类型（从系统配置读取）')
    priority = db.Column(db.String(20), default='一般', nullable=False, comment='优先级：低、一般、高、紧急')

    # 状态与分配
    status = db.Column(db.String(20), default='待处理', nullable=False, comment='工单状态：待处理、处理中、已解决、已关闭')
    assigned_to = db.Column(db.Integer, db.ForeignKey('users.id', ondelete='SET NULL'), nullable=True, comment='分配的维修人员ID')
    assignment_type = db.Column(db.String(20), nullable=True, comment='分配方式：auto（自动）/manual（手动）')

    # 时间记录
    created_at = db.Column(db.DateTime, default=datetime.now, nullable=False, comment='创建时间')
    updated_at = db.Column(db.DateTime, default=datetime.now, onupdate=datetime.now, nullable=False, comment='更新时间')
    assigned_at = db.Column(db.DateTime, nullable=True, comment='分配时间')
    completed_at = db.Column(db.DateTime, nullable=True, comment='完成时间')
    closed_at = db.Column(db.DateTime, nullable=True, comment='关闭时间')

    # 关系定义
    user = db.relationship('User', foreign_keys=[user_id], backref='maintenance_orders')
    room = db.relationship('Room', foreign_keys=[room_id])
    assigned_staff = db.relationship('User', foreign_keys=[assigned_to], backref='assigned_maintenance_orders')
    replies = db.relationship('MaintenanceReply', backref='order', lazy=True, cascade='all, delete-orphan')

    # 约束与索引
    __table_args__ = (
        db.CheckConstraint(
            "status IN ('待处理', '处理中', '已解决', '已关闭')",
            name='check_maintenance_status_valid'
        ),
        db.CheckConstraint(
            "priority IN ('低', '一般', '高', '紧急')",
            name='check_maintenance_priority_valid'
        ),
        db.CheckConstraint(
            "assignment_type IN ('auto', 'manual')",
            name='check_assignment_type_valid'
        ),
        db.Index('idx_mo_order_number', 'order_number'),
        db.Index('idx_mo_user_id', 'user_id'),
        db.Index('idx_mo_room_id', 'room_id'),
        db.Index('idx_mo_status', 'status'),
        db.Index('idx_mo_assigned_to', 'assigned_to'),
        db.Index('idx_mo_maintenance_type', 'maintenance_type'),
        db.Index('idx_mo_created_at', 'created_at'),
        db.Index('idx_mo_priority', 'priority'),
    )

    def __repr__(self):
        return f"<MaintenanceOrder {self.order_number}: {self.title}>"

    @property
    def status_color(self):
        """状态对应的颜色标签"""
        colors = {
            '待处理': 'yellow',
            '处理中': 'blue',
            '已解决': 'green',
            '已关闭': 'gray'
        }
        return colors.get(self.status, 'gray')

    @classmethod
    def generate_order_number(cls):
        """自动生成工单编号：WX + 年月 + 4位序号"""
        today = datetime.now()
        prefix = f"WX{today.strftime('%Y%m')}"
        last_order = cls.query.filter(
            cls.order_number.like(f"{prefix}%")
        ).order_by(cls.id.desc()).first()
        if last_order and last_order.order_number:
            try:
                seq = int(last_order.order_number[-4:]) + 1
            except ValueError:
                seq = 1
        else:
            seq = 1
        return f"{prefix}{seq:04d}"

    @classmethod
    def create(cls, user_id, description, maintenance_type, room_id=None, room_info=None, priority='一般'):
        """创建维修工单"""
        # 标题取描述前20个字
        title = description[:20] + ('...' if len(description) > 20 else '')
        order = cls(
            order_number=cls.generate_order_number(),
            title=title,
            description=description,
            user_id=user_id,
            room_id=room_id,
            room_info=room_info,
            maintenance_type=maintenance_type,
            priority=priority
        )
        db.session.add(order)
        db.session.commit()
        return order

    @classmethod
    def get_by_user_id(cls, user_id):
        """获取指定用户的维修工单"""
        return cls.query.filter_by(user_id=user_id).order_by(cls.created_at.desc()).all()

    @classmethod
    def get_by_assigned_staff(cls, staff_id):
        """获取指定维修人员的工单"""
        return cls.query.filter_by(assigned_to=staff_id).order_by(cls.created_at.desc()).all()

    @classmethod
    def get_pending_orders(cls):
        """获取待处理的工单（用于自动分配）"""
        return cls.query.filter_by(status='待处理', assigned_to=None).order_by(cls.created_at.asc()).all()

    @classmethod
    def auto_assign(cls, order_id):
        """自动分配工单到维修人员（轮询方式）"""
        from models.user import User
        # 查找所有维修员角色的用户
        staff_users = User.query.filter_by(role_code='maintenance_staff', is_active=True).all()
        if not staff_users:
            return None

        # 轮询分配：找当前处理中工单最少的维修员
        min_count = float('inf')
        assigned_user = None
        for staff in staff_users:
            count = cls.query.filter_by(assigned_to=staff.id, status='处理中').count()
            if count < min_count:
                min_count = count
                assigned_user = staff

        if assigned_user:
            order = cls.query.get(order_id)
            if order:
                order.assigned_to = assigned_user.id
                order.assignment_type = 'auto'
                order.assigned_at = datetime.now()
                if order.status == '待处理':
                    order.status = '处理中'
                db.session.commit()
        return assigned_user

    def update_status(self, status, assigned_to=None, assignment_type=None):
        """更新工单状态"""
        self.status = status
        self.updated_at = datetime.now()
        if assigned_to is not None:
            self.assigned_to = assigned_to
            self.assignment_type = assignment_type
            self.assigned_at = datetime.now()
        if status == '已解决':
            self.completed_at = datetime.now()
        elif status == '已关闭':
            self.closed_at = datetime.now()
        db.session.commit()
        return self
```

**设计说明**：
- `order_number` 自动生成，格式为 `WX` + 年月 + 4位序号，如 `WX2026080001`
- `title` 由 `description` 前20个字符自动生成，用户无需输入
- `room_id` 关联 Room 表，自动从用户住宿记录获取，但允许用户修改（nullable=True，不强制锁定）
- `room_info` 冗余存储楼栋+房间号文本，避免每次查询需要 join Room 表
- `assigned_to` 关联 User 表，指向维修员角色用户
- `assignment_type` 记录分配方式（auto/manual），便于统计和审计
- `auto_assign()` 类方法实现轮询分配逻辑：找当前处理中工单最少的维修员

### 3.2 维修回复表 - MaintenanceReply

文件: `models/maintenance/maintenance_reply.py`

```python
from datetime import datetime
from utils.db import db

class MaintenanceReply(db.Model):
    """维修回复表 - 记录工单的回复和处理记录"""
    __tablename__ = 'maintenance_replies'

    id = db.Column(db.Integer, primary_key=True)
    order_id = db.Column(db.Integer, db.ForeignKey('maintenance_orders.id', ondelete='CASCADE'), nullable=False, comment='工单ID')
    user_id = db.Column(db.Integer, db.ForeignKey('users.id', ondelete='CASCADE'), nullable=False, comment='回复用户ID')
    content = db.Column(db.Text, nullable=False, comment='回复内容')
    reply_type = db.Column(db.String(20), default='reply', nullable=False, comment='回复类型：reply(普通回复)/status_change(状态变更)/assignment(分配通知)')
    created_at = db.Column(db.DateTime, default=datetime.now, nullable=False, comment='回复时间')

    # 关系定义
    user = db.relationship('User', backref='maintenance_replies')

    # 约束与索引
    __table_args__ = (
        db.CheckConstraint(
            "reply_type IN ('reply', 'status_change', 'assignment')",
            name='check_reply_type_valid'
        ),
        db.Index('idx_mr_order_id', 'order_id'),
        db.Index('idx_mr_user_id', 'user_id'),
        db.Index('idx_mr_created_at', 'created_at'),
    )

    def __repr__(self):
        return f"<MaintenanceReply {self.id} for Order {self.order_id}>"

    @classmethod
    def create(cls, order_id, user_id, content, reply_type='reply'):
        """创建回复"""
        reply = cls(
            order_id=order_id,
            user_id=user_id,
            content=content,
            reply_type=reply_type
        )
        db.session.add(reply)
        # 更新工单的更新时间
        from models.maintenance.maintenance_order import MaintenanceOrder
        order = MaintenanceOrder.query.get(order_id)
        if order:
            order.updated_at = datetime.now()
        db.session.commit()
        return reply
```

**设计说明**：
- `reply_type` 区分普通回复、状态变更通知、分配通知，前端可按类型展示不同样式
- `status_change` 类型回复记录状态流转信息（如"状态从 待处理 变更为 处理中"）
- `assignment` 类型回复记录分配信息（如"工单已自动分配给维修员 张三"）

8. 若自动分配成功，创建 `assignment` 类型的回复通知

### 5.1 PERMISSIONS 注册表新增项

在 `utils/auth.py` 的 `PERMISSIONS` 字典中新增：

'maintenance': {

    'actions': {
        'view': '查看',
        'create': '新增',
        'edit': '编辑',
        'delete': '删除',
        'manage': '管理',
        'handle': '处理',

**权限说明**：
- `maintenance.view`: 查看维修工单（用户查看自己的工单、维修员查看分配的工单）
- `maintenance.create`: 创建维修工单、回复工单

### 8.2 临时上传机制

**流程设计**：

1. **创建工单页面**: 用户选择照片/视频后，通过 AJAX 调用 `/api/maintenance/temp-upload` 上传到临时目录
2. **临时文件管理**: 每个用户有独立的临时子目录 `maintenance_temp/{user_id}/`
3. **预览展示**: 上传成功后在前端展示预览，文件名记录在隐藏字段中
4. **提交工单**: 创建工单成功后，调用 `move_temp_to_formal()` 将临时文件移动到正式目录
5. **清理策略**: 
   - 提交成功后自动清理临时文件
   - 用户取消创建页面时，前端调用 `/api/maintenance/temp-files/<filename>/delete` 删除
   - 定时清理超过24小时的临时文件（可在应用启动时注册定时任务）

**临时上传 API**:

`/api/maintenance/temp-upload` (POST):
- 请求: multipart/form-data, file 字段
- 响应: `{"success": true, "filename": "xxx.jpg", "url": "/api/maintenance/temp/xxx.jpg"}`

`/api/maintenance/temp-files` (GET):
- 响应: `{"files": [{"filename": "xxx.jpg", "url": "...", "type": "image", "upload_time": "..."}]}`

`/api/maintenance/temp-files/<filename>/delete` (POST):
- 响应: `{"success": true, "message": "临时文件已删除"}`

### 8.3 正式存储与清理

- 工单创建后，照片存储在 `maintenance_photo/{order_id}/` 目录
- 删除工单时，调用 `MaintenancePhotoManager.delete_all_files(order_id)` 清理照片目录
- 照片访问通过 `/api/maintenance/<int:id>/photos/upload` 和 `/api/maintenance/<int:id>/photos/<filename>/delete` 管理

## 九、自动分配逻辑设计

### 9.1 分配策略

**轮询分配（默认策略）**：
1. 查询所有 `is_active=True` 且角色为 `maintenance_staff` 的用户
2. 统计每个维修员当前 `status='处理中'` 的工单数量
3. 选择当前处理中工单最少的维修员
4. 若多个维修员工单数相同，选择ID最小的（先创建的优先）

**分配时机**：
- 用户创建工单后自动触发（`MAINTENANCE_AUTO_ASSIGN_ENABLED` 为 true 时）
- 管理员手动分配时跳过自动分配

### 9.2 分配流程

```
用户创建工单
    ↓
检查 MAINTENANCE_AUTO_ASSIGN_ENABLED 配置
    ↓ (开启)
查询所有活跃维修员
    ↓
有维修员？
    ├─ 是 → 统计各维修员处理中工单数 → 选择最少者 → 分配 → 创建分配通知回复
    └─ 否 → 工单保持"待处理"状态，等待管理员手动分配
    ↓ (关闭)
工单保持"待处理"状态，等待管理员手动分配
```

### 9.3 手动分配

管理员可在工单详情页或列表页手动分配：
1. 从维修员下拉列表中选择
2. 支持批量分配（选择多个待处理工单 + 选择维修员）
3. 手动分配记录 `assignment_type='manual'`

## 十二、数据库迁移

### 12.1 新增表

- `maintenance_orders` - 维修工单表
- `maintenance_replies` - 维修回复表

### 12.2 迁移注意事项

项目使用 SQLAlchemy + Flask，通过 `db.create_all()` 自动建表，无需手动迁移脚本。但需注意：

1. **新增角色数据**: 需在初始化逻辑中创建 `maintenance_staff` 角色并分配默认权限
2. **新增配置数据**: 需在 `_get_default_configs()` 中添加配置项，系统启动时自动初始化
3. **外键约束**: `maintenance_orders.assigned_to` 引用 `users.id`，使用 `SET NULL` 级联，维修员被删除时工单不丢失
