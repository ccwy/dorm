# 部门管理模块设计方案

## 一、模块概述

基于现有宿舍管理系统架构，新增部门管理模块，实现部门字典的统一管理，包括部门列表查看、新增、编辑、删除、批量删除、删除全部、导入导出等功能。删除部门前需验证该部门是否被用户管理（`User.department`）或固定资产管理（`FixedAsset.department_using`、`FixedAsset.department_owning`）引用，若被引用则禁止删除并返回使用详情。

**核心定位**：部门管理模块本质是统一管理"部门字典"，替代现有 `SystemConfig` 中分散的 `ASSET_DEPARTMENTS_USING`、`ASSET_DEPARTMENTS_OWNING` 配置项，同时保持向后兼容——现有 `User` 和 `FixedAsset` 模型仍以字符串字段存储部门名称，不做外键关联改动。每个部门可关联所属公司，实现按公司维度的部门分类管理。

## 二、架构设计原则

严格遵循项目现有架构模式：
- **Blueprint分层模式**: 主蓝图(列表页+搜索+分页) / 操作蓝图(CRUD) / API蓝图(JSON响应+验证接口) / 导入导出蓝图(Excel导入导出+模板下载)
- **模型设计模式**: `__table_args__`(约束+索引) + `@classmethod`类方法
- **配置驱动**: 功能开关 `FEATURE_DEPARTMENT_MANAGE_ENABLED` 从 `SystemConfig` 读取；部门CRUD操作同步更新 `DEPARTMENTS`、`COMPANIES` 配置项，确保现有从 `SystemConfig` 读取部门列表的代码继续正常工作
- **权限控制**: `admin_required` 装饰器 + `login_required` 认证，仅管理员可访问
- **删除验证**: 删除前检查 `User.department`、`FixedAsset.department_using`、`FixedAsset.department_owning` 三处引用，被引用时返回使用详情并禁止删除
- **前端技术栈**: TailwindCSS + FontAwesome + Jinja2模板
- **导入导出模式**: 参照 `fixed_asset_import_export.py`，使用 pandas + openpyxl 实现Excel导入导出

## 三、数据模型设计

### 3.1 部门表 - Department

文件: `models/department.py`

```python
from datetime import datetime
from utils.db import db

class Department(db.Model):
    """部门表 - 统一管理部门字典"""
    __tablename__ = 'departments'

    # 核心字段
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100), nullable=False, comment='部门名称')
    company = db.Column(db.String(100), nullable=True, comment='所属公司')
    description = db.Column(db.String(500), nullable=True, comment='部门描述')

    # 时间记录
    created_at = db.Column(db.DateTime, default=datetime.now, nullable=False, comment='创建时间')
    updated_at = db.Column(db.DateTime, default=datetime.now, onupdate=datetime.now, nullable=False, comment='更新时间')

    # 约束与索引
    __table_args__ = (
        db.UniqueConstraint('name', 'company', name='uq_department_name_company', comment='同公司下部门名称唯一'),
        db.Index('idx_department_name', 'name'),
        db.Index('idx_department_company', 'company'),
    )

    def __repr__(self):
        return f"<Department {self.name} ({self.company})>"

    @classmethod
    def get_all_names(cls):
        """获取所有部门名称列表（用于同步SystemConfig）"""
        departments = cls.query.order_by(cls.name).all()
        return [d.name for d in departments]

    @classmethod
    def get_all_companies(cls):
        """获取所有公司列表（去重，用于同步SystemConfig的COMPANIES配置项）"""
        companies = db.session.query(cls.company).filter(cls.company.isnot(None), cls.company != '').distinct().order_by(cls.company).all()
        return [c[0] for c in companies]

    @classmethod
    def get_by_company(cls, company):
        """根据公司名称获取部门列表"""
        return cls.query.filter_by(company=company).order_by(cls.name).all()

    @classmethod
    def is_name_exists(cls, name, company=None, exclude_id=None):
        """检查部门名称是否已存在（同公司下名称唯一）"""
        query = cls.query.filter_by(name=name)
        if company:
            query = query.filter(db.or_(cls.company == company, cls.company.is_(None)))
        else:
            query = query.filter(cls.company.is_(None))
        if exclude_id:
            query = query.filter(cls.id != exclude_id)
        return query.first() is not None

    @classmethod
    def check_usage(cls, name):
        """
        检查部门名称是否被使用，返回使用详情
        返回: {'used': bool, 'details': dict}
        """
        from models.user import User
        from models.fixed_asset import FixedAsset

        # 检查 User.department
        user_count = User.query.filter_by(department=name).count()

        # 检查 FixedAsset.department_using
        asset_using_count = FixedAsset.query.filter_by(department_using=name).count()

        # 检查 FixedAsset.department_owning
        asset_owning_count = FixedAsset.query.filter_by(department_owning=name).count()

        used = (user_count > 0 or asset_using_count > 0 or asset_owning_count > 0)

        return {
            'used': used,
            'details': {
                'user_count': user_count,
                'asset_using_count': asset_using_count,
                'asset_owning_count': asset_owning_count
            }
        }

    @classmethod
    def create(cls, name, description=None, company=None):
        """创建部门"""
        department = cls(name=name, description=description, company=company)
        db.session.add(department)
        db.session.commit()
        return department

    @classmethod
    def sync_to_system_config(cls):
        """将部门列表同步到SystemConfig的DEPARTMENTS配置项，确保向后兼容；
        同时同步COMPANIES配置项"""
        from models.system_config import SystemConfig
        names = cls.get_all_names()
        config_value = ','.join(names) if names else ''
        SystemConfig.set_config('DEPARTMENTS', config_value)

        # 同步更新 ASSET_DEPARTMENTS_USING 和 ASSET_DEPARTMENTS_OWNING
        SystemConfig.set_config('ASSET_DEPARTMENTS_USING', config_value)
        SystemConfig.set_config('ASSET_DEPARTMENTS_OWNING', config_value)

        # 同步更新 COMPANIES 配置项
        companies = cls.get_all_companies()
        companies_value = ','.join(companies) if companies else ''
        SystemConfig.set_config('COMPANIES', companies_value)
```

**设计说明**：
- `name` 字段不再单独设为 `unique=True`，改为与 `company` 组成联合唯一约束 `uq_department_name_company`，允许不同公司下存在同名部门
- `company` 字段为选填（`nullable=True`），未填写公司的部门之间按 `company=NULL` 判断唯一性
- `is_name_exists()` 方法扩展支持 `company` 参数，检查同公司下名称唯一性
- 新增 `get_all_companies()` 类方法，返回去重后的公司列表
- 新增 `get_by_company()` 类方法，按公司筛选部门
- `sync_to_system_config()` 新增同步 `COMPANIES` 配置项的逻辑
- 不对 `User.department` 和 `FixedAsset.department_using`/`department_owning` 做外键约束，保持字符串存储的向后兼容
- `check_usage()` 类方法用于删除前验证，检查三处引用

### 4.3 操作蓝图路由设计 - department_operations_bp

文件: `blueprints/department_operations.py`

| 路由 | 方法 | 功能 | 操作日志 | 权限 |
|------|------|------|---------|------|
| `/department/operations/add` | POST | 新增部门 | log_operation(module='department') | admin_required |
| `/department/operations/edit/<int:id>` | POST | 编辑部门 | log_operation(module='department') | admin_required |
| `/department/operations/delete/<int:id>` | POST | 删除部门（含使用验证） | log_operation(module='department') | admin_required |
| `/department/operations/batch-delete` | POST | 批量删除部门（含使用验证） | log_operation(module='department') | admin_required |
| `/department/operations/delete-all` | POST | 删除全部部门（含使用验证） | log_operation(module='department') | admin_required |

**操作说明**：
- **新增**: 验证部门名称唯一性（同公司下） → 创建部门记录 → 同步 `SystemConfig`（DEPARTMENTS + COMPANIES） → 记录操作日志
- **编辑**: 验证部门名称唯一性（同公司下，排除自身） → 更新部门记录 → 若名称变更，同步更新 `User.department`、`FixedAsset.department_using`、`FixedAsset.department_owning` 中的旧名称 → 同步 `SystemConfig`（DEPARTMENTS + COMPANIES） → 记录操作日志
- **删除**: 调用 `Department.check_usage()` 验证 → 若被使用则返回使用详情（多少用户、多少资产）并禁止删除 → 若未被使用则删除 → 同步 `SystemConfig`（DEPARTMENTS + COMPANIES） → 记录操作日志
- **批量删除**: 逐个验证每个部门的使用情况 → 仅删除未被使用的部门 → 返回被跳过的部门及原因 → 同步 `SystemConfig`（DEPARTMENTS + COMPANIES） → 记录操作日志
- **删除全部**: 批量验证所有部门 → 仅删除未被使用的部门 → 返回被跳过的部门及原因 → 同步 `SystemConfig`（DEPARTMENTS + COMPANIES） → 记录操作日志

### 4.5 导入导出蓝图路由设计 - department_import_export_bp

文件: `blueprints/department_import_export.py`

参照 `blueprints/fixed_asset_import_export.py` 的实现模式，使用 pandas + openpyxl 实现Excel导入导出。

| 路由 | 方法 | 功能 | 权限 |
|------|------|------|------|
| `/department/import-export/export` | GET | 导出部门数据Excel | admin_required |
| `/department/import-export/import` | POST | 导入部门数据Excel | admin_required |
| `/department/import-export/template` | GET | 下载导入模板 | admin_required |

#### 4.5.1 导出路由 - `/export`

**逻辑流程**：
1. 查询所有部门数据 `Department.query.order_by(Department.company, Department.name).all()`
2. 若无数据，flash提示并重定向回列表页
3. 构建导出数据列表，每行包含：部门名称、所属公司、部门描述、创建时间、更新时间
4. 使用 pandas 生成Excel文件，sheet名为"部门数据"
5. 记录操作日志（module='department', operation_type='batch_import_export'）
6. 返回文件下载响应

**导出字段**：

| 列名 | 字段 | 说明 |
|------|------|------|
| 部门名称 | name | 必填 |
| 所属公司 | company | 选填 |
| 部门描述 | description | 选填 |
| 创建时间 | created_at | 格式: YYYY-MM-DD HH:MM:SS |
| 更新时间 | updated_at | 格式: YYYY-MM-DD HH:MM:SS |

#### 4.5.2 导入路由 - `/import`

**逻辑流程**：
1. 验证上传文件存在且为Excel格式（.xlsx/.xls），限制文件大小10MB
2. 使用 pandas 读取Excel数据
3. 验证必要列：`部门名称`（必填列）
4. 逐行校验并创建部门记录：
   - **部门名称**：必填，同公司下名称唯一（调用 `Department.is_name_exists(name, company)` 检查）
   - **所属公司**：选填，空值视为 `None`
   - **部门描述**：选填，最大500字符
   - **重复数据**：同公司下名称重复的行跳过并记录错误
5. 批量创建成功后，调用 `Department.sync_to_system_config()` 同步配置
6. 记录操作日志，返回导入结果（成功数/失败数/错误详情）

**导入校验规则**：

| 字段 | 规则 |
|------|------|
| 部门名称 | 必填，同公司下名称唯一 |
| 所属公司 | 选填 |
| 部门描述 | 选填，最大500字符 |

**错误处理**：
- 缺少必填列：flash错误提示，重定向回列表页
- 单行校验失败：跳过该行，记录错误信息，继续处理后续行
- 全部失败：flash危险提示，显示所有错误
- 部分成功：flash警告提示，显示成功数和失败详情
- 全部成功：flash成功提示

#### 4.5.3 模板下载路由 - `/template`

**逻辑流程**：
1. 构建模板数据，包含示例行和填写说明行
2. 使用 pandas 生成Excel文件，sheet名为"部门导入模板"
3. 设置列宽，标红必填项说明
4. 记录操作日志
5. 返回文件下载响应

**模板字段**：

| 列名 | 示例值 | 填写说明 |
|------|--------|---------|
| 部门名称 | 技术部、行政部、运营部 | *必填项（同公司下名称唯一） |
| 所属公司 | 总公司、（空）、子公司A | 选填（可留空） |
| 部门描述 | 负责技术研发、负责行政管理 | 选填（最大500字符） |

**配置项说明**：
- `DEPARTMENTS` 配置项的 `is_editable` 设为 `False`，表示该配置项由部门管理模块自动维护，不建议在系统设置页面手动编辑
- `COMPANIES` 配置项的 `is_editable` 设为 `False`，表示该配置项由部门管理模块自动维护，从部门的 `company` 字段去重生成
- 部门管理模块每次CRUD操作后，自动调用 `Department.sync_to_system_config()` 同步更新 `DEPARTMENTS` 和 `COMPANIES` 配置项
- 现有从 `SystemConfig.get_config('ASSET_DEPARTMENTS_USING')` 或 `SystemConfig.get_config('ASSET_DEPARTMENTS_OWNING')` 读取部门列表的代码继续正常工作，因为 `sync_to_system_config()` 会同时更新这两个配置项

## 十、数据库迁移

### 10.1 表结构变更

新增1张表 + 1个字段变更：

- `departments` - 部门表（新增 `company` 字段）

**字段变更详情**：

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `company` | VARCHAR(100) | nullable=True | 所属公司（新增字段） |

### 10.2 约束变更

- **原约束**: `name` 字段 `unique=True`（部门名称全局唯一）
- **新约束**: `name + company` 联合唯一约束 `uq_department_name_company`（同公司下部门名称唯一）
- **新增索引**: `idx_department_company`（company字段索引，用于按公司筛选查询）

### 10.3 迁移注意事项

由于约束从 `name` 单字段唯一变更为 `name+company` 联合唯一，需注意：

1. **已有数据兼容**: 如果 `departments` 表已有数据且存在 `name` 唯一约束，迁移时需：
   - 先删除 `name` 的单字段唯一约束
   - 新增 `company` 字段（允许为空）
   - 新增 `name+company` 联合唯一约束
   - 新增 `idx_department_company` 索引

2. **NULL值处理**: SQL中 `NULL != NULL`，联合唯一约束中 `company=NULL` 的记录彼此不冲突。`is_name_exists()` 方法中对 `company=None` 的情况做了特殊处理，确保未填写公司的部门之间仍能正确检查唯一性。

### 10.4 数据初始化建议

首次启用部门管理模块时，建议的数据初始化策略：

1. **从 `User.company` 去重初始化 COMPANIES**: 查询 `User` 表中 `company` 字段去重后的值，初始化到 `COMPANIES` 配置项
2. **从 `User.department` 去重初始化 DEPARTMENTS**: 查询 `User` 表中 `department` 字段去重后的值，初始化到 `departments` 表和 `DEPARTMENTS` 配置项
3. **关联公司与部门**: 如果 `User` 表同时有 `company` 和 `department` 字段，可按 `(company, department)` 去重后批量插入 `departments` 表，建立公司与部门的关联关系
4. **同步更新**: 初始化完成后调用 `Department.sync_to_system_config()` 同步更新 `DEPARTMENTS`、`COMPANIES`、`ASSET_DEPARTMENTS_USING`、`ASSET_DEPARTMENTS_OWNING` 配置项

项目使用 SQLAlchemy + Flask，通过 `db.create_all()` 自动建表，无需手动迁移脚本。但对于已有数据库的升级场景，建议编写迁移脚本处理约束变更和数据初始化。
